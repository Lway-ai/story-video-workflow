# 视频工作流：从调研到交付

把一部虚构小说改编成竖屏短视频的完整流程。示例影片：63 镜 × 9 秒 = 567 秒，9:16 竖屏，
人物二维卡通、环境实景，旁白 + 字幕 + BGM，ffmpeg 拼合。

## 约定

- **镜**：一支 9 秒的镜头（分镜表的一行）。片头记为 T001，片尾记为 T002，正片按章节编号
  （如 S101、S201……）。
- **首帧**：每镜生成视频用的第一帧静图，1152×2048。
- **一镜到底**：每镜一个连续镜头，无剪切、无转场、无场景切换，机位固定。
- **评级**：每支视频验帧后给三档之一——通过 / 带偏差 / 不通过。
- **全部允许**：开工前和委托方约定一次——已交付的偏差镜头是否接受为候选、不立即重做；
  约定后不再逐批追问，只在触碰底线或实在无法决定时才问。

## 流程总览

```
1 调研 ──→ 2 小说 ──→ 3 分镜表 ──→ 4 首帧 ──→ 5 视频 ──→ 6 帧检与评级
                                                              │
7 旁白 TTS ──→ 8 字幕 ──→ 9 拼合与响度 ──→ 10 校验 ──→ 11 交付
```

## 阶段 1：调研

**目的**：在动笔之前，把事件的事实骨架钉死，区分“已确认”和“绝不能编”。

**输入**：公开报道（新闻、救援队转述、官方公告）、地点实拍资料。

**做法**：

1. 列时间线：出发、关键消息、最后联系、求助、搜救开始、天气变化、找到、确认——
   每条写明来源（哪家媒体、哪天），不写来源的事实不用。
2. 列人物与衣着、装备中**报道确认过**的部分（如失联时上衣、裤子颜色），其余一律视为
   未确认，不得写进骨架。
3. 列**必须纠正**的清单：容易写错的地名、把“推测方向”误当成“证实去过”的地点、
   把“推测地点”误当成“发现地点”的地点、禁令线路与实际路线的混淆。
   经验：救援推测方向 ≠ 证实到访地点 ≠ 发现地点，三者要分开写。
4. 列**绝不能虚构为事实**的清单（写进简报，见阶段 2）：
   精确路线、坠落过程与高度、确切死亡时间与医学死因、遗体姿态 / 伤情等细节、
   完整装备清单、家属报警的具体时刻与对话、家庭背景、未证实的搜救手段
   （如搜救犬、热成像仪）、无记录的追偿 / 处罚。
5. 地点实拍：山、村镇背景必须用真实地点的实拍照片，不用 AI 生成的通用山村。
   找图时记下每张图的来源、尺寸、天气、画面里有没有人、有没有可读文字。
   **注意**：有些地点（如一棵孤立的古树）可能根本找不到确认过的实拍图——
   找不到就记为“未找到”，不要拿长得像的树顶替，也不要在小说里硬写它。

**输出**：调研简报（骨架 + 纠正清单 + 禁写清单），即
[`templates/brief-template.md`](../templates/brief-template.md) 的填充版。

**检查**：骨架里的每一条事实都能指到来源；禁写清单里的每一项都在简报里出现了。

## 阶段 2：小说（DeepSeek 重写 + 脚本化校对）

**目的**：得到一篇细节非常详细、可直接拆成 63 镜的小说。小说是全片唯一的情节来源，
分镜表、旁白都从它来，不另编情节。

**输入**：阶段 1 的调研简报。

**做法**：

### 2.1 写简报

按 [`templates/brief-template.md`](../templates/brief-template.md) 填：人名处理（全部化名，
只有名字虚构，时间、地点、衣着、事件经过按报道写）、已确认骨架、必须纠正、
绝不能虚构清单、小说要求（章结构、细节密度、虚构演绎的写法、目标镜数）、
开头要求（一句前提旁白：谁、什么时候、在哪里、经过什么事件、永远留在那里；
说完这一句，再从头讲起）。

### 2.2 调模型写初稿

用 [`scripts/call-deepseek-novel.py`](../scripts/call-deepseek-novel.py)，分**两次调用**：

- 第 1 次：第一部分（爬山遇险弧线：出发 → 环境恶化 → 最后一条消息 → 失联为止），约 5000 字。
- 第 2 次：把第一部分全文作为上下文，写第二部分（搜寻弧线：搜救展开 → 找到的那一刻，
  只写衣物和雨衣覆盖远景），约 4000 字。

参数（示例影片实测）：模型 `deepseek-chat`，`temperature 1.0`，`max_tokens 8192`。
系统提示词：“你是一位擅长写悬疑纪实风格小说的中文作家。只输出小说正文，
不要加任何解释、前言或总结。”

**密钥规则**：API Key 只从环境变量 `DEEPSEEK_API_KEY` 读，当次调用用完即弃，
不写进任何文件、记忆或聊天记录；以后再用需重新提供或走安全存储。
`finish_reason` 为 `length` 表示被截断，要加 `max_tokens` 或分段重写。

### 2.3 通读校对（必须做，模型一定会写错）

把初稿全文通读一遍，逐条核对简报的骨架和禁写清单。示例影片的初稿出现过这些问题，
校对时按种类处理（见 [`scripts/proofread-fix.py`](../scripts/proofread-fix.py) 的骨架）：

| # | 问题种类 | 例子与处理 |
|---|---|---|
| 1 | **结构性矛盾** | 第一部分写主角下撤后活着回到民宿、喝汤、睡觉，与事实和第二部分自相矛盾。整段删掉，改为下撤入雾、失联、此后无记录的收束。 |
| 2 | **时间锚点错误** | 关键消息的时间写错（如写成 8:34，实为 9:02），上午时间线整体后移半小时，最后一条消息的时间不动。 |
| 3 | **人物身份写错** | 民宿主人写成另一身份；用户已定不写的动物（牛、狗）出现在文中，全部删掉。 |
| 4 | **人物锁定不一致** | 背包颜色、鞋子颜色与锁定不符；补上锁定里的特征（发型、虎牙等）。 |
| 5 | **遗留物品逻辑错误** | 穿戴的衣物和随身充电宝不可能留在民宿——改写为旅行包里的换洗衣服和充电线；手机和充电宝随主角上山。 |
| 6 | **人名未化名** | 救援队长、队员用了报道中的真名或错名，一律改回化名。 |
| 7 | **发现场景越线** | 写了遗体姿态、手机反光等细节——全部删掉，只留无人机屏幕上的一小块颜色。 |
| 8 | **地点推测未标注** | 搜寻会上提及某地点方向时，必须写明只是推测（“猜的，猜测不能当路线用”）。 |
| 9 | **语言混写** | 中英混写（如英文单词插进中文服装描写），改为纯中文。 |
| 10 | **开头时间表述** | “三天后搜救”改为具体日期，与搜救开始日对上。 |

校对方法：**脚本化**。把每处改动写成 `(原文, 改文, 出现次数)` 的替换表，
每条断言恰好出现指定次数再替换；另设禁写词表（改后必须一条都不剩）和必备词表
（改后必须都在）；改动记入文件末尾的“校对改动”脚注，注明改了什么、为什么。

**输出**：小说定稿（示例影片：约 8260 字）+ 校对改动脚注。

**检查**：禁写词（精确路线、坠落过程、死亡时间、遗体细节等）全文搜索为零；
关键时间锚点与调研简报一致；全部人名都是化名。

**底线（全片通用）**：

- 不拍 / 不写精确路线、坠落过程、死亡时间、遗体细节。
- 消息、清单、草稿只用旁白转述，画面绝不出现文字。
- 发现段只拍衣物和雨衣覆盖远景；无人机画面只拍灰屏和一小块颜色，不做假画面。

## 阶段 3：分镜表

**目的**：把小说拆成可执行的镜头清单。这是全片的唯一施工图：首帧、视频、旁白、
字幕、拼合全部按它来，现场不再发明情节。

**格式**：CSV（UTF-8-SIG），9 列，见
[`templates/shots-table-template.csv`](../templates/shots-table-template.csv)：

| 列 | 说明 |
|---|---|
| 镜号 | T001（片头）、S101……、T002（片尾）；按章节顺序编号 |
| 章节 | 所属章节（如“七月一日”“七月三日”） |
| 开始秒 | 第 i 镜 = (i−1)×9，从 0 开始；每镜 9 秒 |
| 时长秒 | 固定 9 |
| 场景 | 地点 + 时间 + 天气 |
| 动作（一镜到底） | 本镜内真实发生的连续动作，一个空间、固定机位、无剪切 |
| 首帧来源 | 实拍参考图文件名，或“新做” |
| 浓缩旁白 | 由小说原句浓缩，不添新事实；消息、清单、草稿只用旁白转述 |
| 备注/不拍 | 本镜的禁拍项（如“手机屏幕无文字”“不拍坠落”） |

**做法**：

1. 总镜数 63，每镜 9 秒，总长 567 秒；开始秒用脚本校验 `(i−1)×9`，错一位全片错位。
2. 旁白：63 句，共约 1500 字（示例影片 1486 字），最长一句 34 字；
   每句浓缩自小说原句，不添新事实。T001 为一句前提旁白（见阶段 2.1 开头要求）。
3. 表头写死**人物锁定**（示例：主角——黑低马尾、蓝色上衣、红色裤子、灰绿色背包、
   沙色低帮徒步鞋、两颗小虎牙、黑色一字夹；配角各一行外貌特征）和**风格**
   （人物二维卡通，环境实景，雪山和村镇背景用真实地点实拍，人物按中国人面孔，
   画质柔和、不刻意锐利）。
4. 表头写死**底线**（见阶段 2 末尾），每镜的“备注/不拍”再写本镜的具体禁项。
5. 首帧来源：室外镜头优先引用实拍参考图；室内、人物特写、屏幕类镜头写“新做”。
   **引用前必须先读原图**：核对天气、是否有人群、是否有可读文字——
   与小说不符的图不能用（示例影片：引用图里出现徒步人群、晴天粉花树，与雨雾不符，
   只能改新做）。
6. 全部新做、无复用：旧版服装与新小说不符的首帧、视频一律不复用。

**输出**：分镜表 MD + CSV（两者由脚本从同一来源生成，保持一致）。

**检查**：63 行、开始秒连续无错位；旁白总字数、最长句记录在案；
禁写词（坠落、死亡时间、遗体等）在动作列和旁白列全文搜索为零；
无人机、发现、衣物类镜头的“备注/不拍”已写明只拍屏幕色块 / 只拍衣物。

## 阶段 4：首帧

**目的**：每镜一张 1152×2048 的首帧静图。首帧决定视频的构图、人物、场景，
视频生成时以它为第一帧，所以首帧错了，视频一定错。

**输入**：分镜表 + 实拍参考图。

**做法**：

1. 每批 **4 镜**（图片生成上限：每轮 4 张）。按分镜表顺序做，不跳镜。
2. 提示词要素（缺一不可）：场景（分镜表场景列）+ 动作起始状态 + **人物锁定全文** +
   “画面中不出现任何可读文字” + “画质柔和，不用过分清晰”。
   手机类镜头加一句“手机屏幕是黑的，没有文字”。
3. 实拍参考图优先：有引用图的镜头，先用原图编辑（保留真实地点质感）；
   原图内容与小说冲突（有人群、天气不对、有牛狗等用户已定不写的元素）时，
   改为全新生成，不硬用。
4. 全新生成时，把真实地点的样子写进提示词（开阔草甸 / 密竹林 / 灰白碎石坡 /
   雾中山路等），而不是“美丽的山”这种通用描写。
5. 逐张验帧再进入下一批：人物锁定是否全（发型、衣着颜色、背包、鞋、虎牙、
   发夹）、场景是否对、画面有无可读文字、有无多余的人或动物、有无与小说矛盾的元素。
   验不过的当场重做（示例影片：某批 4 张里 3 张因实拍图有人群、晴天粉花而重做，
   重做后全部通过）。

**常见首帧偏差**（记下来，别在视频阶段再发现）：

- 发夹画成蝴蝶 / 星星 / 蝴蝶结等形状（锁定是黑色一字夹，模型经常画错）。
- 鞋子颜色变深（湿 / 泥泞时易画成深灰），外套被风吹成披风状。
- 物品细节：背包侧袋多一根登山杖、充电宝带小红点、包装出现小字。
- 场景与小说矛盾：晴天、粉花树、木栈道、观景台等小说没有的元素。

**输出**：`shots/<镜号>-firstframe.png`（1152×2048），每批一张状态记录。

**检查**：4 张全部通过才做视频；重做过的首帧注明原因和版本号。

## 阶段 5：视频（图生视频）

**目的**：把首帧变成 9 秒的一镜到底视频。

**输入**：首帧 + 分镜表动作列。

**做法**：

1. 每批 **6 镜**（视频生成上限：每条消息 6 支新视频）。
2. 提示词模式（固定结构，只换动作部分）：

   > 首帧图片 + “固定机位，一镜到底。” + 分镜表动作列 + 人物锁定 +
   > “画面中不出现任何可读文字。画质柔和，不用过分清晰。”
   >
   > 手机类镜头加“手机屏幕是黑的，没有文字。”

   **提示词里只给画面和动作**：不写旁白、不写后期说明、不写角色图例，
   那些是后期加的，写进提示词会被模型烧进画面。
3. 输出规格（实测，改不了）：**每支固定 10.00 秒、704×1248、24fps**，
   无论请求几秒。拼合时只截前 9 秒。
4. 只做一次：每镜按原提示词试一次；技术失败最多纠 2 次、总共 3 次；
   服务拒绝则永久停止，不重试、不换说法绕过（见阶段 6）。

**输出**：`shots/<镜号>.mp4`（10.00 秒）。

**检查**：时长、分辨率、帧率用 ffprobe 核对；音频只测电平（全文件 volumedetect 的
mean/max），不逐秒听验——听验留到校验阶段抽查。

## 阶段 6：帧检与评级

**目的**：在拼合之前，知道每一镜能不能用、哪里偏了。自己的帧检不是最终验收，
但没有它，拼合就是盲拼。

**做法**：

1. 每支视频抽 **3 帧：0.5s / 4.5s / 9.2s**，并排看：构图是否还是首帧的构图，
   动作是否真实发生、是否按分镜表顺序发生，人物、服装、场景是否一致。
2. 评级三档：
   - **通过**：机位固定、动作真实、人物一致、无可读文字。
   - **带偏差**：动作和人物大体对，但有机位移动 / 场景变化 / 模型加字等偏差，
     偏差按秒数记下来（如“约 4 秒起推近”“9.2 秒换成另一条巷子”）。
   - **不通过**：违反底线或无法使用（如屏幕出现聊天界面、安检门大字可读、
     尾段切到另一个场景）。
3. 每批写一份状态文件（`BATCH-<N>-STATUS.md`）：逐镜 verdict + 偏差描述 +
   音频电平 + 交付记录。63 镜结束时汇总总账。
4. 缺镜处理：**首帧被工具安全检查拦下时，不重试、不换说法绕过**。
   记录下来，等委托方决定“换个说法再试”还是“跳过这镜”；在决定之前，
   拼合时保留该镜时位，用黑场配旁白（见阶段 9），不伪造画面、不拿别的画面顶替。
5. 评级结果不追完美：示例影片 62 支视频里，通过 7 支、不通过 4 支、带偏差 51 支，
   绝大多数偏差都是机位问题。按开工前的约定（“全部允许”），带偏差镜头作候选交付，
   不立即重做；不通过镜头记下来，等整片拼完再决定是否重做。

**输出**：每批状态文件 + 63 镜总账。

**检查**：总账的数字加起来等于总镜数（通过 + 带偏差 + 不通过 + 缺镜 = 63）；
每支不通过镜头都写明了原因和秒数。

## 阶段 7：旁白 TTS

**目的**：把分镜表旁白列的 63 句录成旁白音轨，每句对位本镜，每句不超过 9 秒。

**输入**：分镜表 CSV 的“浓缩旁白”列。

**做法**（见 [`scripts/tts-narration.py`](../scripts/tts-narration.py)，源自实测脚本）：

1. 声音：固定一位男声（示例影片用 A 号男声，悬疑感），全片同一声音、同一语速基准。
2. 基准语速 **125**（工具参数 `--speed`，范围 1–200，默认 100）。
   语速 100 时约 4.37 字/秒，125 时约 5.30 字/秒，但逐句差异很大，
   语速效果不单调——**必须逐句实测时长，不能按字数估算**。
3. 逐句渲染为 WAV，文件名 `NN-<镜号>.wav`（NN 为镜序号，从 01 开始）。
   渲染后逐句测时长，**超过 8.8 秒的句重录**：先提速到 150，再到 175；
   仍超长则改标点断句重录（示例影片：某句拆成 3 句、句间留 0.25 秒空隙才塞下，
   一字不删）。
   示例影片 v2 重制版：63 句总长 270.272 秒，最长 T001 7.62 秒、最短 S803 1.89 秒，
   全部 ≤8.8 秒，无需提速重录；上一版曾有 12 句在 150 重录、1 句在 175 重录。
4. **TTS 输出的 WAV 头部带 ID3v2 标签**：测时长前必须先剥离
   （读 10 字节头，用第 7–10 字节的 synchsafe 尺寸算出标签总长并切掉，
   有 footer 时再加 10 字节），否则 ffprobe 读不到正确时长。
   同一文本 + 同一语速的 TTS 输出是确定的，可复现。

**输出**：`narration/NN-<镜号>.wav`（63 个）+ 时长表（每句秒数，超长句标出）。

**检查**：63 句齐全；每句 ≤8.8 秒；总时长记录在案。

## 阶段 8：字幕

**目的**：由分镜表 + 旁白实测时长生成 SRT 字幕和镜头映射表。

**做法**（见 [`scripts/gen-subs.py`](../scripts/gen-subs.py)，源自实测脚本）：

1. 每条字幕：序号 = 镜序号；开始 = 镜开始秒 + 0.2 秒；结束 = 开始 + 该句旁白实测时长；
   文本 = 分镜表旁白列原文。
2. 需要顶置的字幕（如牌面文字那镜的旁白字幕，避免与牌面文字重叠），
   文本前加 `{\an8}`。
3. 同时生成镜头映射表 `shot-map.txt`，每行 `<镜号> <视频文件>`；
   缺镜的行写 `BLACK`（见阶段 9）。
4. 字幕样式（烧录时用，阶段 9）：`FontName=Noto Sans CJK SC, FontSize=22，
   PrimaryColour=&HFFFFFF, OutlineColour=&H80000000, BorderStyle=1, Outline=2，
   Shadow=1, Alignment=2, MarginV=30`。

**输出**：`subs.srt`（63 条）+ `shot-map.txt`（63 行）。

**检查**：SRT 条数 = 镜数；每条起止时间落在对应镜的 9 秒内（开始 +0.2 秒，结束 ≤ 开始 + 9 秒）；
映射表里缺镜已标 BLACK。

## 阶段 9：拼合与响度

**目的**：把 63 个 9 秒段落拼成一支成片，加字幕、BGM、淡入淡出，响度达标，
输出 540p 交付版 + 704p 母版。

**输入**：镜头视频 + 旁白 WAV + SRT + BGM + 镜头映射表。

**做法**（见 [`scripts/build-segments.sh`](../scripts/build-segments.sh) 和
[`scripts/build-final.sh`](../scripts/build-final.sh)，源自实测脚本）：

### 9.1 段落（每镜一个 9 秒 MP4）

每个段落：视频 `trim=0:9`（只取生成视频的前 9 秒）→ `scale` 到 704×1248
（等比缩小后居中 pad）→ `fps=24`；音频 = 原片环境音 ×0.35（`volume=0.35`）
+ 旁白（`adelay=200|200`，即旁白晚 0.2 秒进）混音（`amix`）。

- **缺镜段落**：9 秒纯黑视频（`color=c=black:s=704x1248:r=24:d=9`）+
  旁白（配静音环境轨），保留镜位，不伪造画面。
- **牌面文字（可选步骤）**：牌面文字不由生成模型画，后期用 `drawtext` 合成。
  做法：先从实际视频帧里量出牌面位置（示例：蓝牌 x 295–433、y 757–819，
  704×1248 画面），再把文字写进文本文件，用 `fontsize=16, x=316, y=768`
  的参数烧在牌面上；抽帧核对字在牌上、且与顶置旁白字幕无重叠。
- 编码：libx264，`preset medium`，`crf 20`，`pix_fmt yuv420p`，音频 AAC 128k、48kHz、立体声。

### 9.2 拼接与烧录

1. 按映射表顺序 concat 63 个段落（`-video_track_timescale 24`），得无字幕母版。
2. 烧字幕（FontSize 22，见阶段 8）+ 视频淡入 1 秒（`fade=t=in:st=0:d=1`）+
   片尾渐黑 1.5 秒（从总长 −1.5 秒起，如 567 秒片从 565.5 秒起）。
3. BGM：钢琴 + 弦乐循环（`-stream_loop -1`），音量 **0.12**，片头 2 秒淡入、
   片尾从总长 −5 秒起 5 秒淡出；与原声音轨混音时加 `normalize=0`
   （否则 amix 的归一化会把响度算错）。
4. 音频淡入淡出与视频同步：音频淡入 1 秒，片尾从总长 −1.5 秒起 1.5 秒淡出。

### 9.3 响度（最容易翻车的一步）

目标：**−14 LUFS，True Peak ≤ −1 dBTP**。

1. 先测 preloud 版：`loudnorm=I=-14:TP=-1:LRA=11:print_format=json`，
   记下 `input_i / input_tp / input_lra / input_thresh / target_offset`。
   （示例影片 preloud：I −30.89 / TP −9.34 / LRA 13.10 / thresh −41.97 / offset 1.48。）
2. 双遍 loudnorm 应用：`loudnorm=I=-11.5:TP=-2.2:LRA=11:measured_I=…:…:linear=true`
   （I/TP 用比目标低的值，给限幅留余量）。
   （示例：双遍后 −14.50 LUFS / −0.98 dBTP。）
3. **再过一遍纯限幅**：`alimiter=limit=0.80:level=false`。
   **level=false 必须显式写**——alimiter 默认 `level=true` 会自动提增益，
   实测把成片从 −14.50 推到 −12.71 LUFS、真峰值 +0.61 dBTP（+1.79 LU 增益），
   等于没限幅反而推高；改成 `level=false` 后复测 −14.56 LUFS / −1.24 dBTP / LRA 5.60，
   两项都过。注意：同一条命令在别的素材上曾“恰好”通过，行为与输入有关——
   永远显式写 `level=false`，不要赌。
4. 540p 交付版：由 704p 母版 `scale=540:960`、`crf 23` 转出，**音频直接复制母版**
   （`-c:a copy`），响度与母版一致。
5. 全程大文件中间步骤放项目目录，**不要放 /tmp**（见文末技术教训第 1 条）。

**输出**：`final-567s-704p.mp4`（母版）+ `final-567s-540p.mp4`（交付版）+
无字幕母版、响度处理前母版（留档备查）。

**检查**：两版时长、帧数、尺寸；响度复测 −14 LUFS 左右、TP ≤ −1 dBTP。

## 阶段 10：校验

**目的**：交付前最后一遍核对。只做测量和读帧，不改内容。

**做法**：

1. **黑帧检测**：`blackdetect` 找全片黑段。注意本机 ffmpeg 的阈值参数是 **`pic_th`**，
   不是 `picture_th`（旧参数名会让检测静默失败）。
   预期：只有缺镜那一处黑段（示例：184.499–189.041 秒，4.54 秒，即缺镜镜内字幕结束后的部分），
   其余无黑帧。
2. **抽帧读**：至少读这几个时间点——0.5 秒（淡入中 + T001 字幕）、
   9.5 秒（S101 字幕落在画面上）、缺镜时段（纯黑，均值亮度 0.0）、
   牌面文字那镜（字在牌上 + 顶置字幕无重叠）、T002 附近（字幕）、
   566.5 秒（渐黑进行中）。
3. **音频淡入淡出**：分段测电平——首 1 秒、尾 1.6 秒、中段参考各测一次
   （示例：首 1 秒 mean −17.6 dB；尾 1.6 秒 mean −37.9 dB / max −19.5 dB；
   中段 mean −17.3 dB）。**注意**：`volumedetect` + 输出端 `-ss` 会给出
   扁平、错误的读数——正确做法是把窗口先截成 WAV，再按 0.1 秒分格算峰值 / RMS。
   音频只做电平核验，不逐秒听验——如实写进记录。
4. **文件核对**：时长、总帧数（如 567.112 秒、13608 帧）、尺寸、md5、
   540p 与母版响度一致。

**输出**：校验记录（写进最终状态文件）。

**检查**：黑段数量与缺镜数一致；抽帧点全部通过；响度复测通过。

## 阶段 11：交付

**目的**：把成片交到委托方手里——**交付的成立标准是对方能下载、能播放**，
不是“我发出去了”。

**做法**：

1. **直接发原生附件**：每个视频单独发一个可播放附件，不只放进 ZIP
   （ZIP 里的下载按钮在对方的自动化入口不一定能导出到本地）。
   拼合版发 540×960（CRF 23，手机上能看）；单镜保持生成分辨率；高清母版存盘备查。
2. **不走分享链接**：分享页链接会过期（示例：某次链接 2 天后过期），
   且无法从本机验证对方是否下载成功。附件通道出问题时（如对方反复报“找不到视频”），
   停下来找别的路，不要反复重发同一条路。
3. 交付时附上：总时长、镜数、缺镜说明、评级汇总、响度数值、已知保留项。
   明确写“待对方下载播放、逐镜验收”，不把自己的帧检说成最终验收。

**输出**：交付记录（文件名、大小、md5、交付时间、对方反馈）。

**检查**：对方确认能播放，才算交付完成；未确认前不启动下一部。

## 附录 A：常见失败模式与对策

按示例影片 62 支视频的实测统计：最常见的失败不是动作错，而是机位和文字。

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 机位推近 / 平移 / 切镜 | 0.5 秒还是首帧构图，4.5 秒已推成中景、9.2 秒成特写；或中途换角度、换背景 | 提示词固定写“固定机位，一镜到底”；帧检三帧对照，偏差按秒数记；接受为候选，不为“好看”重生成 |
| 尾段场景切换 | 前 5 秒干净，7–9 秒切到另一条巷子、另一座山、竹林溪边 | 同上；拼合时只用前 5 秒干净段的，另行说明（示例：某两镜只用前 5 秒全景，后接示意图） |
| 模型自己加文字 | 首帧素面的盒子 / 饼干包装 / 方便面 / 地图 / 招牌，视频里印上可读汉字或英文（如“COMPRESSED BISCUIT”、地名、乱码臂章） | 提示词写明物品素面无字；帧检重点查 4.5 秒和 9.2 秒；违规镜头评不通过，重生成视频（首帧不动） |
| 手机屏幕出现界面 | 屏幕亮起，显示评论列表、聊天界面（气泡 + 文字行） | 首帧和提示词都写“手机屏幕是黑的，没有文字”；违规即不通过。注意：屏幕只剩淡淡灰光、无可读字时不算违规 |
| 参考图天气 / 人群不对 | 引用图是晴天、粉花树、徒步人群，与小说的雨雾、独行不符 | 引用前先读原图；冲突时改全新生成，不要硬用 |
| 人物锁定漂移 | 发夹变蝴蝶 / 星星 / 蝴蝶结；鞋子变色；外套鼓成披风；多一只手、多一个包；姐姐“没腿” | 每批首帧逐张验锁定；人物参考图固定用同一张已通过的首帧；手数、腿数、包数逐帧数 |
| 场景加戏 | 小说只写“只听见水声”，视频里出现瀑布；小说没写的木栈道、观景台、公鸡、红顶建筑出现在背景 | 帧检时对照分镜表“备注/不拍”；远景小元素记为偏差，近景大元素影响评级 |
| 首帧被安全检查拦下 | 某镜首帧生成被拒（如举手机拍照发群的画面） | 不重试、不换说法绕过；记录，等委托方定重说还是跳过；拼合时黑场配旁白保留镜位 |
| 旁白超长 | 某句 >8.8 秒，塞不进 9 秒镜 | 提速 150 → 175 → 改标点断句（拆句 + 0.25 秒空隙），一字不删 |
| 响度翻车 | loudnorm 后 TP 超标，或 alimiter 默认参数反推增益 | 见阶段 9.3：双遍参数留余量 + `alimiter level=false` + 复测 |

## 附录 B：技术教训

示例影片生产中踩过的坑，按严重程度排列。带 ★ 的是会直接毁掉一次拼合的。

1. ★ **/tmp 是 512MB tmpfs，会撑满**。一次拼合做到一半因 /tmp 写满而失败。
   大文件中间步骤一律放项目目录，/tmp 只放一次性小文件。
2. ★ **alimiter 必须显式加 `level=false`**。默认 `level=true` 会自动提增益
   （实测 +1.79 LU），把限幅器变成放大器。见阶段 9.3。
3. ★ **loudnorm 的 TP 限幅器在 PCM 域会 overshoot 约 +1.8 dB**。
   只靠 loudnorm 的 TP 参数不够，必须在后面再加一遍纯限幅（alimiter level=false）。
4. **loudnorm 的增益响应在高峰值因数素材上弱 / 非单调**：测出来的参数不要迷信，
   应用后必须复测，不达标就调参再跑。
5. **blackdetect 的阈值参数是 `pic_th`，不是 `picture_th`**。旧参数名在本机 ffmpeg 上
   不存在，会导致检测静默失败（输出为空还以为没黑帧）。
6. **volumedetect + 输出端 `-ss` 会给出扁平、错误的读数**。正确做法：
   先把窗口截成 WAV，再按 0.1 秒分格算峰值 / RMS；整文件 volumedetect 只测 mean/max。
7. **TTS 输出的 WAV 头部带 ID3v2 标签**：测时长前先剥离（10 字节头，
   用 synchsafe 尺寸算标签长），否则 ffprobe 读不到正确时长。见阶段 7。
8. **生成视频固定 10.00 秒、704×1248、24fps**，无论请求几秒。拼合时截前 9 秒；
   不要在生成阶段纠结时长参数。
9. **跨设备移动文件不要用 `os.replace`**（/tmp → 项目目录会报 Errno 18），用 `shutil.move`。
10. **批量上限**：图片每轮 4 张、视频每条消息 6 支，超过会失败或丢结果。
    分镜表按 4 镜一批做首帧、6 镜一批做视频。
11. **生成工具的提示词参数是数组**：`prompt` 须传 `[{kind, value}, …]` 结构，
    传纯字符串会失败。
12. **生成的文件名是小写的**，glob 区分大小写；写脚本匹配时注意大小写。
13. **上下文中断后，第一次调用媒体工具可能报一次延迟命名空间错误**，
    立即重试一次即可成功，不是真正的拒绝。
14. **脚本里读文件不要用 shell 的 `read VAR < file` 写在一行命令里**——
    曾静默失败过。把值写死进脚本，或用 `python3 -c` / 独立脚本文件读。
15. **远程存储上传要用绝对路径或 `~/` 路径**，相对路径会失败；且上传链接会过期，
    不要把它当作唯一交付渠道（见阶段 11）。
